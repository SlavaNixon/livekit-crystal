# Голосовая комната: Crystal (Kemal) + LiveKit

Тестовый проект голосового чата в браузере.

- **LiveKit** — медиасервер (WebRTC, TURN встроен), запускается в Docker.
- **Crystal + Kemal** — небольшой бэкенд: отдаёт страницу и выдаёт токены доступа (`/api/token`).
- **public/index.html** — страница с `livekit-client` (JS): вход в комнату, микрофон, список участников.

## Запуск

```bash
docker compose up --build
```

Откройте <http://localhost:3000> в двух вкладках (или двух браузерах), введите разные имена и одну комнату. Разрешите доступ к микрофону. Для проверки используйте наушники, иначе будет эхо.

Остановить: `docker compose down`.

Если Docker Desktop (Windows/macOS) жалуется на `is not shared from the host`, значит где-то монтируется файл из папки, не добавленной в File Sharing. В этой версии проекта файлы не монтируются, так что такой ошибки быть не должно.

## Как это работает

1. Браузер запрашивает `GET /api/token?name=...&room=...` у Crystal-приложения.
2. Приложение подписывает JWT (HS256) API-секретом LiveKit. Отдельный SDK не нужен, токен собирается в `src/app.cr`.
3. Браузер подключается к LiveKit (`ws://localhost:7880`) с этим токеном и публикует звук с микрофона.
4. LiveKit пересылает звук остальным участникам комнаты.

## Проверка с другого устройства в локальной сети

1. Скопируйте `.env.example` в `.env`, укажите IP компьютера в `NODE_IP` и `LIVEKIT_PUBLIC_URL` (например, `ws://192.168.1.50:7880`).
2. Браузер даёт доступ к микрофону только на `localhost` или по HTTPS. С другого устройства нужен HTTPS: самый простой путь — туннель (`ngrok`, `cloudflared`) или обратный прокси с сертификатом (Caddy). Для HTTPS-страницы адрес LiveKit тоже должен быть `wss://`.

## Если нет звука

- Проверьте, что порты `7880/tcp`, `7881/tcp`, `7882/udp` свободны и не блокируются файрволом.
- На Linux, если Docker не пробрасывает UDP как нужно, можно запустить сервис `livekit` с `network_mode: host`. На Docker Desktop (macOS/Windows) host-режим не работает, там оставьте проброс портов.
- Откройте консоль браузера (F12): ошибки подключения видны там.

## Продакшен

- Замените `LIVEKIT_API_KEY` и `LIVEKIT_API_SECRET` на свои (`openssl rand -hex 32`).
- Добавьте аутентификацию на `/api/token`: сейчас токен выдаётся любому, кто знает адрес.
- Поставьте HTTPS и настройте домен для LiveKit (см. документацию LiveKit по деплою и TURN).
